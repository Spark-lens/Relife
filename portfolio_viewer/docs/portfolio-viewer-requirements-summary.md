# Portfolio Viewer VS Code 插件需求摘要

## 1. 项目目标

设计一个 VS Code 插件，将 TradingView 投资组合和 Watchlist 的核心浏览体验迁移到 VS Code 中，支持美股和 A 股。

第一阶段重点是视觉和交互：使用 VS Code 原生侧边栏展示投资组合、Watchlist 分类和标的信息。组合计算暂不追求完整复刻，先展示现有持仓数据。

## 2. 已确认的范围

- 使用 VS Code 原生侧边栏作为主要界面。
- 侧边栏直接展示分类下的多个标的。
- 点击标的只改变选中状态，不打开详情页或其他内容。
- 右侧 VS Code 编辑区暂时留白，为后续功能预留。
- 参考 TradingView Watchlist 的信息密度和展示方式。
- 暂时忽略二级分类，只保留一级分类。
- 支持美股和 A 股标的。

## 3. 侧边栏结构

建议结构如下：

```text
HOME
├── 投资组合
└── watchlist
    ├── 现金流
    ├── 大盘
    ├── 股息
    ├── 个股
    ├── 杠杆
    └── 比特币
```

分类节点展开后直接列出标的。标的行暂定显示：

- 标的代码
- 标的名称
- 最新价格
- 涨跌幅

后续可根据免费行情接口能力补充涨跌额、市场、交易状态等字段。

## 5. 本地数据

投资组合数据从本地 CSV 读取，不直接连接 TradingView。

当前交易流水文件：

`/mnt/d/workspace-codex/Relife/data/tradingview/tradingview_full_latest_2026-07-29.csv`

当前 CSV 字段：

```text
Symbol, Side, Qty, Fill Price, Commission, Closing Time
```

该文件是交易流水，可用于展示或重建现有持仓；它不是 Watchlist 快照，因此 Watchlist 分类和白名单需要由插件内置或使用独立配置维护。

CSV 中已出现的交易类型包括：

- Buy
- Sell
- Dividend

## 6. 行情数据

行情数据使用免费的外部数据接口获取，暂不要求用户配置 API Key。

本地 CSV 负责：

- 投资组合交易流水
- 现有持仓数据
- Watchlist 分类和标的白名单

免费行情接口负责：

- 最新价格
- 涨跌额
- 涨跌幅
- 其他可获得的 Watchlist 展示字段

行情供应商应保留可替换能力，避免插件绑定单一接口。

## 7. 刷新与时区

- 默认时区：`Asia/Shanghai`
- 界面时间按上海时间显示。
- 按 A 股和美股各自交易日历判断是否刷新。
- 默认在各市场开盘前 15 分钟和开盘后 15 分钟各获取一次行情。
- 后续建议增加手动刷新入口。

## 8. 交互原则

- 分类节点支持展开和折叠。
- 标的显示在分类节点下。
- 点击标的只高亮当前选中项。
- 不跳转到详情页。
- 不在第一阶段打开图表或额外 Webview。
- 右侧编辑区保持空白。
- 侧边栏应保持紧凑，优先保证多个标的可以同时浏览。

## 9. 视觉方向

- 以 VS Code 原生 TreeView 为基础，保持与编辑器一致的导航体验。
- 参考 TradingView Watchlist 的紧凑表格信息密度。
- 参考其正负涨跌颜色和快速扫描方式。
- 图标采用 TradingView 风格的简洁、线性、低装饰视觉语言。
- 不直接复制 TradingView 的品牌 Logo、专属图标资源或品牌标识。

## 10. 暂不实现

- TradingView 双向同步。
- 实时行情流或高频刷新。
- 完整 TradingView 投资组合计算复刻。
- 详情页、图表页和独立 Webview。
- 二级分类。
- 复杂的已实现盈亏、股息再投资、汇率换算和公司行为处理。

## 11. 后续需要确认

1. 免费行情接口的具体供应商及其 A 股、美股覆盖范围。
2. CSV 与白名单标的之间的代码映射规则，例如 `NASDAQ:XQQI`、`XQQI`、`512100` 等格式。
3. 投资组合节点需要展示的持仓字段，例如数量、平均成本、成本金额和当前市值。
4. Watchlist 是否允许用户在插件内新增、删除和移动标的。
5. 行情接口失败或达到限流时的缓存与错误提示策略。
